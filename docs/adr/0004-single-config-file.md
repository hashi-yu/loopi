# 0004 設定は `loopi.config.json` 1 枚。探索は 2 段、環境変数はモデル指定だけを上書きする

状態: 採用

## 背景

対象リポジトリごとに基準ブランチ、テストコマンド、保護パスが違う。一方で、ホームディレクトリの設定や複数ファイルのマージを許すと「どの値が効いているか」が実行ログから追えなくなり、パイプラインの停止理由を切り分けにくくなる。

## 決定

- 設定ファイルは `loopi.config.json` 1 枚。探索は `--config <path>` の明示指定 → リポジトリルート、の 2 段だけ。ホームディレクトリや親ディレクトリは見ない
- 設定はリポジトリのルートから読む。作業フォルダにある設定は使わない（実装担当が設定を変えても、その実行には影響しない）
- 既定値は `src/config.ts` の `DEFAULTS` に置き、入れ子はキー単位で上書きする
- `test.command` だけは必須。無ければ起動しない
- 環境変数で上書きできるのはモデル指定（`PI_PROVIDER` / `PI_MODEL` / `PI_EFFORT` / `CLAUDE_MODEL` / `CLAUDE_EFFORT` / `CODEX_MODEL` / `CODEX_EFFORT`）だけ。試しに別モデルで回す用途に限る

## 結果

- 設定の読み込みと検証は副作用のない処理に保ち、`tests/config.test.ts` で検証する
- 新しい設定キーを足すときは、`Config` 型・`DEFAULTS`・`loadConfig` のマージ・README と `docs/spec/config.md` の表、をそろえて更新する
