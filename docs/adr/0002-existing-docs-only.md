# 0002 参照ドキュメントは既にあるものを使い、`init` は勝手に作らない

状態: 採用

## 背景

パイプラインの判断の質は、issue 本文と、仕様（spec）・設計判断（ADR）・共通ルール（AGENTS.md）の質で決まる。しかしこれらは対象リポジトリの持ち物で、loopi の雛形を置いても中身が空なら「読むべき文書がある」と各エージェントに誤解させるだけになる。

## 決定

- `loopi init` が書くのは loopi 自身のもの（`loopi.config.json`、`.claude/skills/loopi-run/`、無ければ `.claude/settings.json`）だけ
- `AGENTS.md` / `CLAUDE.md`、`docs/spec/` 系、`docs/adr/` 系、`.github/ISSUE_TEMPLATE/` は、あるものを検出して設定に載せる。無ければ「何のために必要か」を添えて提案するだけで、ファイルは置かない
- `docs` の指定はすべて任意。指定されたものだけがプロンプトに載り、何も無ければ案内文ごと落とす

## 結果

- 文書が薄いリポジトリでも動くが、レビューは「テストが通っているか」しか見られない。それを README で明示する
- 対象リポジトリの作法（ファイル名や置き場）を loopi が決めない
