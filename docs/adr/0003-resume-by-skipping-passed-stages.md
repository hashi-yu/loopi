# 0003 再実行は成功済みの工程をスキップして続きから進む

状態: 採用

## 背景

1 回の実行は数分〜数十分かかり、途中で止まる原因の多くはパイプラインの外にある（認証切れ、利用上限、レビューで人間の判断が必要、issue の補足）。止まるたびに実装からやり直すと、時間と費用が無駄になるうえ、実装が毎回変わってレビューの記録が積み上がらない。

## 決定

再実行時は、次の条件で工程をスキップする。

| 条件 | スキップ |
|---|---|
| 作業フォルダに基準ブランチとの差分がある | 初回実装 |
| 保存済みのレビュー合格キーが、現在の差分と issue 本文から計算したキーと一致する | 一次レビューと取捨選択（記録は保存済みのものを使う） |
| 保存済みの最終レビューキーが一致する | 最終レビュー（結果は保存済みのものを使う） |

- キーは `sha256(差分 + issue本文)` の先頭 16 文字。差分か issue のどちらかが変われば無効になる
- 保存先は `logs/issue-<番号>.state.json`。`--fresh` で捨てる。マージ完了時に消す
- 実装をやり直したいときは作業フォルダを消す。パイプラインは消さない

## 結果

- issue を補足して再実行すると、実装はそのままでレビューだけやり直される（issue がキーに入っているため）
- 作業フォルダがそのまま残るので、人が対面で直してから再実行できる
- 作業フォルダの再利用時、基準ブランチの取り込みはマージ直前まで行われない（issue #5 で見直し中）
